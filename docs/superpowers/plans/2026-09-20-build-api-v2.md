**Goal:** Make the existing `/api/v1/` genuinely useful for an AI building projects: add
**lookup reads** (so it can pick valid FK values), **requirements/completeness/cost reads** (so it
can reason about what a project needs / what's missing), **search** (find existing parts/projects
to reuse), and a **duplicate-as-variant** endpoint. Read-mostly, additive — no model changes.

**Architecture:** Extends the merged DRF app (`core/api/`, PR #40). All new endpoints reuse
existing model methods/managers; no new models, no migration (authtoken already present).

**Tech Stack:** Django 6.0 + DRF, Python 3.13, SQLite, ruff 0.15.20, DRF `APITestCase`.

## Endpoints to add (all under `/api/v1/`)

- `GET /spoolman-filaments/` — list `SpoolmanFilamentMapping` (`spoolman_filament_id`,
  `spoolman_filament_name`, `spoolman_color_hex`) so a client can pick a valid filament id.
- `GET /print-presets/` — list instantiable `OrcaPrintPreset`
  (`filter(state=OrcaPrintPreset.STATE_RESOLVED, instantiation=True)`) → id + name, for `part.print_preset`.
- `GET /projects/{id}/requirements/` — `{total_parts_count, total_filament_grams,
  total_filament_meters, filament_requirements, hardware_requirements, total_hardware_cost,
  variant_progress}` (call the existing Project methods).
- `GET /projects/{id}/validate/` — completeness check: list issues — parts without `stl_file`,
  parts without `spoolman_filament_id`, parts with `estimation_status == ERROR`, and whether the
  project has any parts at all. Return `{ok: bool, issues: [{part_id, part_name, issue}]}`.
- Search: add DRF `SearchFilter` to the existing `ProjectViewSet` and `PartViewSet`
  (`filter_backends=[filters.SearchFilter]`, `search_fields=["name", ...]` incl. `material` for parts)
  → `GET /projects/?search=` / `GET /parts/?search=`.
- `POST /projects/{id}/duplicate/` — `{name}` → `Project.duplicate_as_variant(name,
  created_by=request.user)`, returns the new project (ProjectManage perm).
